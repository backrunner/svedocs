# Quick Start

svedocs is a SvelteKit-native documentation framework for teams that want the common docs stack in one place: content loading, routing, theme, search, Ask AI, SEO, Open Graph images, checks, and Cloudflare deployment helpers.

The fastest way to learn it is to scaffold a project, inspect the generated files, and then replace the starter content with your own documentation.

## Create a site

```sh
pnpm create svedocs my-docs --template docs
cd my-docs
pnpm install
pnpm dev
```

Open the local URL printed by the dev server. The `docs` template gives you a working SvelteKit app with a docs layout, sample content, local search, Ask AI fallback routes, sitemap, robots, and Open Graph routes.

Use a smaller template when you want less surface area:

| Template | Use it when |
| --- | --- |
| `minimal` | You want the smallest SvelteKit docs shell and will add integrations later. |
| `docs` | You want a complete local docs experience with search, Ask AI fallback, SEO, and OG routes. |
| `cloudflare` | You plan to deploy to Cloudflare Pages and want Wrangler bindings from the start. |

## What svedocs gives you

| Layer | What it does |
| --- | --- |
| Content | Scans Markdown, MDX-style, and SVX files, reads frontmatter, extracts headings, validates links, and builds a page manifest. |
| Navigation | Generates sidebars, previous/next links, route metadata, localized page scopes, and table-of-contents data from the same manifest. |
| Theme | Provides a Svelte theme, Tailwind CSS v4 variables, light/dark modes, code blocks, diffs, callouts, forms, and docs layouts. |
| Search | Creates page and section records for local MiniSearch, Algolia, Typesense, and Cloudflare AI Search. |
| Ask AI | Uses the same records for citations and supports mock, Cloudflare AI Search, Workers AI, and OpenAI-compatible providers. |
| SEO | Produces metadata, canonical URLs, alternates, JSON-LD, sitemap, robots, and build-time or route-based OG images. |
| CLI | Runs create, dev, build, check, index, OG generation, Cloudflare helpers, and dependency upgrades. |

## Project anatomy

A generated project has a deliberately small shape:

```txt
my-docs/
  content/
    docs/
      index.md
    pages/
      index.md
  src/routes/
    [...path]/+page.svelte
    api/search/+server.ts
    api/ask/+server.ts
    og/[...path]/+server.ts
    sitemap.xml/+server.ts
    robots.txt/+server.ts
  svedocs.config.ts
  vite.config.ts
  svelte.config.js
```

Most day-to-day work happens in `content/docs`, `content/pages`, and `svedocs.config.ts`. The route files are intentionally thin: they load virtual modules generated by the Vite plugin and pass them to the default theme or runtime helpers.

## Write your first page

Create `content/docs/getting-started.md`:

````md title="content/docs/getting-started.md"
---
title: Getting Started
description: Learn the first workflow in this product.
order: 2
---

# Getting Started

Use this page to explain the first successful path.

## Install

```sh
pnpm add your-package
```
````

svedocs maps the file to `/docs/getting-started`, adds it to the sidebar, extracts `Install` for the page table of contents, and creates search records for both the page and section.

## Development workflow

Use the CLI while writing:

```sh
pnpm dev
pnpm check
pnpm build
```

`svedocs check` catches missing descriptions, duplicate routes, duplicate canonical URLs, broken internal links, missing anchors, missing assets, translation gaps, and package export issues when requested.

## Production checklist

Before shipping a public docs site:

- Set `site.name`, `site.title`, `site.description`, and `site.url`.
- Give every important page a unique `description`.
- Run `svedocs check --strict`.
- Decide whether the site should build as `edge`, `static`, or `spa`.
- Configure search and Ask AI providers only after local content is stable.
- Keep secrets in environment variables or `.dev.vars`, never in committed docs files.
- Generate or route OG images for pages that will be shared publicly.
